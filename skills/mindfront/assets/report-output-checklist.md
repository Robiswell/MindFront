# Report Output Checklist

- Strict validation passed.
- Unit tests passed.
- Compile checks passed.
- Unsupported and support-candidate claims remain visible.
- Limitations are present.
- "What to test next" is present.
- Simulated findings are separated from validated signals.
- Task-observation protocols are labeled as collection handoffs, not evidence.
- Task-validation fixtures and real task observations keep separate evidence grades.
- When a DB path is used, the improvement plan is generated and labeled as an operational backlog, not market evidence or proof of adoption, conversion, performance lift, or C-suite impact.
- Editable source path is recorded.
- Final output path is recorded.
- Document-workflow handoff path is recorded.
- Planned PDF output path is recorded.
- PDF status is explicit when no PDF was rendered.
- If a PDF was rendered, the documentation-flow result records a non-empty PDF and visual QA status.
